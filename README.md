# Веб-система регистрации учетных записей

Первый рабочий каркас для создания учетных записей работников в Active Directory и Zimbra.


## Состав полной версии

В архив включены:

- основное веб-приложение;
- локальная, гибридная и AD-аутентификация операторов;
- подключение к AD по LDAPS;
- подключение к Zimbra по SSH-ключу, SSH-паролю или в автоматическом режиме;
- обычный Compose и отдельный Compose для развертывания из Git-репозитория через Portainer;
- пример переменных окружения без реальных паролей;
- модульные тесты;
- `.gitignore` для Python, PyCharm, локальных данных и секретов;
- `.dockerignore`, исключающий служебные файлы из Docker-образа.

## Что уже реализовано

- первоначальный вход по локальному логину и паролю;
- режимы авторизации `local`, `hybrid` и `ad`;
- ограничение AD-входа членством в заданной группе;
- вставка двух строк: ФИО и личный email, в любом порядке;
- автоматический разбор ФИО на отдельные поля с возможностью исправления;
- проверка ФИО на случайные латинские и иные символы не из русской раскладки;
- последовательный подбор логина: `фамилия.ио` → `фамилия.и` → `фамилия`, затем расширение буквами имени или отчества без порядковых номеров;
- проверка занятости только по логину в AD и во всех настроенных доменах Zimbra;
- ручной ввод собственного логина;
- создание пользователя AD через LDAPS;
- создание ящика Zimbra через SSH и `zmprov`, с аутентификацией по ключу или паролю;
- два режима почтовых доменов: отдельный выбор или основной домен с алиасами;
- почтовый пароль длиной 16 символов;
- временный пароль AD из частей имени и фамилии, двух цифр и спецсимвола;
- отображение всех реквизитов оператору после успешной операции;
- отправка логина и пароля почты на личный email;
- отправка логина и пароля AD на новую корпоративную почту;
- журнал операций без паролей;
- установка `accountExpires` в AD и даты `ДД.ММ.ГГГГ` в `zimbraNotes`;
- безопасный режим `DRY_RUN=true`.

## Заполняемые атрибуты AD

При создании пользователя записываются:

- `sn` – фамилия;
- `givenName` – имя;
- `displayName` – `Фамилия Имя Отчество`;
- `mail` – созданный корпоративный адрес;
- `sAMAccountName` – выбранный логин;
- `userPrincipalName` – логин с настроенным UPN-суффиксом.

Совпадения ФИО отдельно не ищутся. Уникальность определяется только повторной проверкой логина в AD и Zimbra непосредственно перед созданием.

## Важное ограничение пароля AD

Пароль, составленный из имени и фамилии, предсказуемее полностью случайного. Поэтому он рассматривается только как временный. По умолчанию включено `AD_FORCE_CHANGE_AT_FIRST_LOGON=true`.

## Быстрый запуск в DRY-RUN

```bash
cp .env.example .env
# Обязательно замените APP_SECRET_KEY и BOOTSTRAP_ADMIN_PASSWORD
docker compose up -d --build
```

Интерфейс будет доступен на `http://server:8080`.

При `DRY_RUN=true` создается только запись в локальном журнале. AD, Zimbra и SMTP не изменяются.

## Переход с локального входа на AD

Сначала оставьте:

```dotenv
AUTH_MODE=hybrid
AD_LOGIN_ENABLED=false
```

После настройки LDAPS:

```dotenv
AUTH_MODE=hybrid
AD_LOGIN_ENABLED=true
AD_ALLOWED_GROUP_DN=CN=Account Provisioning Operators,OU=Groups,DC=example,DC=local
```

После проверки локальный вход можно отключить:

```dotenv
AUTH_MODE=ad
```

## Active Directory

Для установки пароля через LDAP требуется защищенное соединение. Заполните:

```dotenv
AD_SERVER=dc01.example.local
AD_PORT=636
AD_USE_SSL=true
AD_VERIFY_TLS=true
AD_CA_CERT_FILE=/run/secrets/ad-ca.pem
AD_BASE_DN=DC=example,DC=local
AD_USERS_OU=OU=Users,DC=example,DC=local
AD_BIND_DN=CN=svc-provisioner,OU=Service Accounts,DC=example,DC=local
AD_BIND_PASSWORD=...
AD_UPN_SUFFIX=example.local
# Несколько DN групп разделяются точкой с запятой, так как сами DN содержат запятые.
AD_DEFAULT_GROUP_DNS=CN=Base Users,OU=Groups,DC=example,DC=local;CN=VPN Users,OU=Groups,DC=example,DC=local
```

Служебной учетной записи следует делегировать только необходимые права на целевую OU и группы:

- создание и удаление объектов пользователей;
- чтение пользователей;
- запись нужных атрибутов;
- сброс пароля;
- изменение членства только в разрешенных группах.

При создании пользователь сначала создается отключенным, затем устанавливается пароль, после чего учетная запись включается.

## Zimbra

### Два самостоятельных домена

```dotenv
ZIMBRA_DOMAINS=example.ru,example.com
ZIMBRA_DOMAIN_MODE=separate
```

Оператор выбирает домен в форме.

### Основной домен и алиасы

```dotenv
ZIMBRA_DOMAINS=example.ru,example.com
ZIMBRA_DOMAIN_MODE=primary_alias
ZIMBRA_PRIMARY_DOMAIN=example.ru
ZIMBRA_CREATE_ALIASES=true
```

Будет создан основной адрес `login@example.ru` и алиас `login@example.com`.

### SSH-доступ

Поддерживаются три режима SSH-аутентификации:

```dotenv
# Закрытый ключ
ZIMBRA_SSH_AUTH=key
ZIMBRA_SSH_PRIVATE_KEY=/run/secrets/zimbra_ssh_key

# Пароль
ZIMBRA_SSH_AUTH=password
ZIMBRA_SSH_PASSWORD=сложный-пароль-технического-пользователя

# Автоматически: сначала существующий файл ключа, иначе пароль
ZIMBRA_SSH_AUTH=auto
```

Вместо передачи пароля через переменную окружения можно указать файл:

```dotenv
ZIMBRA_SSH_AUTH=password
ZIMBRA_SSH_PASSWORD_FILE=/run/secrets/zimbra_ssh_password
```

Файл предпочтительнее, поскольку значение обычной переменной окружения доступно администраторам Portainer и может быть видно через сведения о контейнере. В любом режиме требуется корректный `known_hosts`: проверка ключа SSH-сервера намеренно не отключается.

Для первого подключения по паролю через Portainer достаточно добавить в переменные стека:

```dotenv
ZIMBRA_SSH_AUTH=password
ZIMBRA_SSH_HOST=mail.example.local
ZIMBRA_SSH_PORT=22
ZIMBRA_SSH_USER=provisioner
ZIMBRA_SSH_PASSWORD=пароль-технического-пользователя
```

`ZIMBRA_SSH_PRIVATE_KEY` в этом режиме не используется.

Контейнер передает команды `zmprov` через stdin. Пароль создаваемого почтового ящика не включается в аргументы удаленного процесса. SSH-пароль используется только библиотекой Paramiko при установлении соединения и не записывается приложением в журнал.

На сервере Zimbra потребуется отдельный технический пользователь и строго ограниченное правило `sudoers`, разрешающее запуск только `/opt/zimbra/bin/zmprov` от имени `zimbra`. Команда запускается через `sudo -n`, поэтому пароль SSH не заменяет правило `sudoers`: запрос пароля для `sudo` недопустим. Не используйте SSH-доступ root.

Перед запуском создайте:

```bash
mkdir -p secrets certs data
ssh-keyscan -H mail.example.local > known_hosts
```

Для режима ключа поместите закрытый ключ в `secrets/zimbra_ssh_key`. Сертификат центра сертификации AD поместите в `certs/ad-ca.pem`.

## Увольнение

Форма увольнения выполняет две операции:

1. В AD устанавливает `accountExpires` на 00:00 следующего дня после указанного последнего рабочего дня.
2. В Zimbra записывает дату в `zimbraNotes` в формате `ДД.ММ.ГГГГ`.

Сама запись даты в `zimbraNotes` не блокирует ящик. Отдельный планировщик, который в нужный день меняет `zimbraAccountStatus`, следует добавить после выбора требуемого статуса: `locked`, `closed` или другого рабочего сценария.

## Локальные операторы

После запуска дополнительного локального оператора можно создать командой:

```bash
docker compose exec account-provisioner python scripts/create_local_user.py operator1 --role operator
```

Пароль хранится только в виде Argon2-хеша.
